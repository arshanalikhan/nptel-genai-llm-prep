Formula sheet

Numericals worth easy marks

Management-school NPTEL papers mix concept MCQs with short calculations. These are the formulas that can be asked from this syllabus; the exam gives an on-screen calculator.

Text representation (W1)

TF(t,d)  = count of t in d / words in d
IDF(t)   = log( N / df(t) )
TF-IDF   = TF × IDF
cos(a,b) = a·b / (‖a‖ ‖b‖)

A word in every document has IDF = log 1 = 0, so its TF-IDF is 0. Cosine similarity ignores length; 1 = same direction, 0 = orthogonal.

Vocabulary of V words → one-hot vector of length V; embeddings are dense, length d ≪ V.

RNN size (W2)

h_t = tanh(W_hh h_(t−1) + W_xh x_t + b)
params(simple RNN) = h·h + h·x + h
LSTM  = 4 × (h·h + h·x + h)
GRU   = 3 × (h·h + h·x + h)

LSTM has 4 gate blocks (forget, input, candidate, output); GRU has 3 (update, reset, candidate). Keras adds the Dense output layer separately.

Attention (W3)

Attention(Q,K,V) = softmax( QKᵀ / √d_k ) V
multi-head: d_k = d_model / h
self-attention cost ∝ n² · d
softmax(z)_i = e^(z_i) / Σ e^(z_j)

Dividing by √d_k keeps dot products from growing with dimension, which would push softmax into tiny gradients. Original transformer: d_model 512, 8 heads → d_k = 64.

Decoding (W5)

p_i = e^(z_i/T) / Σ e^(z_j/T)
T → 0 : greedy (argmax)   T = 1 : unchanged
T > 1 : flatter, more random
perplexity = exp( −(1/N) Σ log p(w_i) )

Top-k keeps the k most likely tokens; top-p (nucleus) keeps the smallest set whose probabilities add to ≥ p. Lower perplexity = better language model.

Fine-tuning size (W6)

LoRA on W (d × k), rank r:
  trainable = r × (d + k)
full update = d × k
memory (weights only) = params × bytes
  fp32 4 B · fp16/bf16 2 B · int8 1 B · int4 0.5 B
full training ≈ 16–20 B per parameter

1B params in fp32 = 4 GB just to load; training with Adam needs about 4–5× that (gradients, optimizer states, activations). Chinchilla: compute-optimal training uses ~20 tokens per parameter.

Evaluation (W6)

ROUGE-1 recall    = overlap unigrams / unigrams in reference
ROUGE-1 precision = overlap unigrams / unigrams in output
F1 = 2PR / (P + R)
BLEU = BP × exp( Σ wₙ log pₙ )  (precision, n = 1..4)

ROUGE → summarization (recall oriented). BLEU → translation (precision oriented, with a brevity penalty). Both only count word overlap, not meaning.

Worked examples

Text and vectors

PracticeTF-IDF

TF-IDF of one word

A corpus has 1,000 documents; "transformer" appears in 10 of them. In a 100-word document it appears 5 times. Using log base 10, what is its TF-IDF in that document?

Show the working
  1. TF5 ÷ 100 = 0.05
  2. IDFlog₁₀(1000 ÷ 10) = log₁₀ 100 = 2
  3. Multiply0.05 × 2 = 0.1

TF-IDF = 0.1

Trap: a word like "the" in all 1,000 docs gets IDF = log 1 = 0, however often it appears.

PracticeCosine

Cosine similarity

a = (1, 2, 2) and b = (2, 0, 1). What is cos(a, b)?

Show the working
  1. Dot product1·2 + 2·0 + 2·1 = 4
  2. Lengths‖a‖ = √(1+4+4) = 3 ‖b‖ = √(4+0+1) = √5 ≈ 2.236
  3. Divide4 ÷ (3 × 2.236) = 4 ÷ 6.708 ≈ 0.596

cos ≈ 0.60

PracticeRNN

Parameters in recurrent layers

Input size x = 10, hidden size h = 20. How many parameters in a SimpleRNN, an LSTM and a GRU layer (with biases, one bias vector per gate)?

Show the working
  1. One block h·h + h·x + h400 + 200 + 20 = 620
  2. SimpleRNN1 × 620 = 620
  3. LSTM 4 gates4 × 620 = 2,480
  4. GRU 3 gates3 × 620 = 1,860

620 · 2,480 · 1,860

Trap: Keras's default GRU (reset_after=True) uses two bias vectors per gate, giving 1,920. Read the question's assumption.

Attention and decoding

PracticeAttention

One attention step

d_k = 4. A query q scores two keys with raw dot products q·k₁ = 4 and q·k₂ = 0. Values v₁ = 10, v₂ = 2. What is the attention output?

Show the working
  1. Scale divide by √d_k = 2scores = 2, 0
  2. Softmaxe² = 7.389, e⁰ = 1 weights = 7.389/8.389, 1/8.389 = 0.881, 0.119
  3. Weighted sum of values0.881 × 10 + 0.119 × 2 = 8.81 + 0.24 = 9.05

≈ 9.05

Trap: skipping the √d_k scaling gives weights 0.982 / 0.018 and output ≈ 9.86.

PracticeMulti-head

Head size and projection weights

d_model = 768 with 12 heads. What is d_k, and how many weights are in the Q, K, V and output projections of one attention layer (ignore biases)?

Show the working
  1. Head size768 ÷ 12 = 64
  2. Each projection d_model × d_model768 × 768 = 589,824
  3. Four of them W_Q, W_K, W_V, W_O4 × 589,824 = 2,359,296 ≈ 2.36 M

d_k = 64; ≈ 2.36 M weights (4d²).

Trap: the feed-forward block (d → 4d → d) adds 8d², so a whole layer is ≈ 12d².

PracticeTemperature

Softmax with temperature

Logits for two tokens are 2 and 0. What is P(first token) at T = 1 and at T = 2?

Show the working
  1. T = 1e² / (e² + 1) = 7.389 / 8.389 = 0.881
  2. T = 2 divide logits by 2 → 1 and 0e¹ / (e¹ + 1) = 2.718 / 3.718 = 0.731

0.88 at T = 1, 0.73 at T = 2: higher temperature flattens the distribution.

PracticeTop-p

Which tokens survive nucleus sampling?

Next-token probabilities: cake 0.40, bread 0.25, pie 0.15, soup 0.10, rock 0.06, car 0.04. With top-p = 0.8, which tokens can be sampled? With top-k = 2?

Show the working
  1. Sort and accumulate0.40 → 0.65 → 0.80 ✓ stop
  2. Top-p set{cake, bread, pie}, renormalised ÷ 0.80
  3. Top-k = 2{cake, bread}

Top-p 0.8 → cake, bread, pie. Top-k 2 → cake, bread.

Fine-tuning and evaluation

PracticeLoRA

LoRA trainable parameters

A weight matrix is 512 × 64 (as in the original transformer's per-head projection). LoRA uses rank r = 8. How many trainable parameters, and what fraction of the full matrix?

Show the working
  1. Full matrix512 × 64 = 32,768
  2. LoRA matrices A is r × k, B is d × rA: 8 × 64 = 512 B: 512 × 8 = 4,096 total = 4,608
  3. Fraction4,608 ÷ 32,768 ≈ 14% (86% fewer)

4,608 trainable parameters, about 14% of the original.

Trap: the base weights are frozen; after training you can merge W + BA, so inference latency doesn't change.

PracticeMemory

GPU memory for a model

A 7-billion-parameter model. How much memory do the weights need in fp32, fp16 and int4? Roughly how much for full fine-tuning at ~20 bytes/parameter?

Show the working
  1. fp327e9 × 4 B = 28 GB
  2. fp16 / bf167e9 × 2 B = 14 GB
  3. int47e9 × 0.5 B = 3.5 GB
  4. Full training weights + gradients + Adam states + activations7e9 × 20 B = 140 GB

28 GB · 14 GB · 3.5 GB · ≈ 140 GB to train, which is why PEFT and quantization matter.

PracticeROUGE

ROUGE-1 recall, precision, F1

Reference: "it is cold outside" (4 words). Output: "it is very cold outside" (5 words). Find ROUGE-1 recall, precision and F1.

Show the working
  1. Overlapping unigramsit, is, cold, outside = 4
  2. Recall ÷ reference length4 ÷ 4 = 1.0
  3. Precision ÷ output length4 ÷ 5 = 0.8
  4. F12 × 1.0 × 0.8 ÷ 1.8 = 0.889

R = 1.0, P = 0.8, F1 ≈ 0.89

Trap: "it is not cold outside" gets the same scores although it means the opposite.

Week notes

What each week covers

Each week opens with a diagram of its main idea. Points tagged KEY are the ones most likely to become MCQs. The course outline lists 7 content weeks; the official summary says 8 weeks, so the last one is likely revision.

W1W2W3W4W5W6W7Course map
01NLP

Natural Language Processing

  • KEYNLP tasks: classification (sentiment, spam), named entity recognition, POS tagging, machine translation, summarization, question answering, text generation. NLU = understanding; NLG = generation.
  • KEYPreprocessing: tokenization (split into tokens), lowercasing, stop-word removal, stemming (crude suffix chopping, "studies" → "studi", may not be a word) vs lemmatization (dictionary form using vocabulary + POS, "better" → "good").
  • Tokenization levels: word, character, subword. Subword methods (BPE, WordPiece, SentencePiece) handle rare and unseen words by splitting them into known pieces, so there is no out-of-vocabulary problem.
  • KEYBag of words: word counts, ignores order and grammar. n-grams keep some local order (bigram = 2 words). TF-IDF down-weights words common across documents; a word in every document scores 0.
  • One-hot: length = vocabulary size, every pair of words is equally distant (orthogonal), so no similarity information; very sparse.
  • KEYWord embeddings: dense vectors learned from context ("you shall know a word by the company it keeps" — distributional hypothesis). Word2Vec: CBOW predicts the word from its context (faster, good for frequent words); Skip-gram predicts the context from the word (better for rare words). Negative sampling speeds training.
  • GloVe uses global co-occurrence counts; FastText uses character n-grams so it can build vectors for unseen words. These are static: "bank" has one vector for river and money. Contextual embeddings (ELMo, BERT) fix this.
  • Similarity: cosine similarity is the standard; analogies work by vector arithmetic.
  • Classic models: Naive Bayes and logistic regression on TF-IDF are strong baselines for text classification. Evaluate with accuracy, precision, recall, F1.
02Sequences

Sequential data, RNNs, encoder–decoder

  • KEYSequential data: order matters (text, speech, time series, stock prices). Feed-forward nets take fixed-size input and have no memory; RNNs share the same weights across time steps and carry a hidden state.
  • RNN shapes: one-to-many (image captioning), many-to-one (sentiment), many-to-many aligned (POS tagging), many-to-many unaligned = seq2seq (translation).
  • KEYTraining: backpropagation through time (BPTT). Repeated multiplication by the same weights causes vanishing gradients (can't learn long-range dependencies) or exploding gradients (fixed by gradient clipping).
  • KEYLSTM: a cell state plus forget, input and output gates; the additive cell update lets gradients flow, so it remembers long-range context. GRU: update and reset gates, no separate cell state, fewer parameters, often similar accuracy.
  • Bidirectional RNN: reads left-to-right and right-to-left; useful when the whole input is available (tagging), not for generating the next word.
  • KEYEncoder–decoder (seq2seq): encoder compresses the input into a context vector; decoder generates the output. Weakness: fixed-length context bottleneck, worse on long sentences.
  • Teacher forcing: in training the decoder gets the true previous token rather than its own prediction (faster, but train/test mismatch called exposure bias).
  • Decoding: greedy picks the best token each step; beam search keeps the top-B partial sequences (B = 1 is greedy).
  • RNNs process tokens one at a time, so training can't be parallelised across the sequence; transformers remove that limit.
03Attention

Attention mechanism and transformers

  • KEYWhy attention: instead of one context vector, the decoder takes a weighted sum of all encoder states at each step, so long sentences keep detail. Bahdanau (additive) and Luong (multiplicative/dot) attention were the first versions for seq2seq.
  • KEYScaled dot-product: softmax(QKᵀ/√d_k)V. Scaling stops large dot products saturating softmax. Weights are non-negative and sum to 1.
  • KEYTransformer ("Attention Is All You Need", Vaswani et al., 2017): no recurrence or convolution; encoder and decoder stacks (6 each in the original) of multi-head attention + position-wise feed-forward, each with a residual connection and layer normalisation.
  • Positional encoding: attention has no sense of order, so position information (sine/cosine or learned) is added to the token embeddings.
  • Masked self-attention in the decoder hides future tokens so prediction of token t only sees tokens before t (causal/autoregressive).
  • Cross-attention: decoder queries attend to encoder keys and values.
  • Multi-head: different heads learn different relations (syntax, coreference). d_k = d_model / h.
  • Cost: self-attention is O(n²) in sequence length — the reason context windows are limited — but all positions are computed in parallel, unlike RNNs.
  • KEYThree families: encoder-only (BERT: masked LM, bidirectional, good for classification/NER), decoder-only (GPT: next-token prediction, generation), encoder–decoder (T5, BART: translation, summarization).
04GenAI

Introduction to Generative AI

  • KEYDiscriminative vs generative: discriminative models learn P(y | x) and draw boundaries (logistic regression, classifiers); generative models learn P(x) or P(x, y) and can create new samples.
  • Types of GenAI output: text (LLMs), images (DALL·E, Midjourney, Stable Diffusion), audio/music, video, code, synthetic data. Business uses: content, marketing copy, chatbots, summarising documents, code assistants, design.
  • KEYAutoencoder: encoder compresses to a bottleneck (latent code), decoder reconstructs; trained on reconstruction loss; used for dimensionality reduction, denoising, anomaly detection. A plain autoencoder's latent space has gaps, so sampling from it gives poor images.
  • KEYVAE: encoder outputs a mean and variance; z is sampled with the reparameterisation trick (z = μ + σ·ε) so gradients can flow; loss = reconstruction + KL divergence to a standard normal, which makes the latent space continuous so you can sample. Outputs tend to be blurry.
  • KEYGAN (Goodfellow, 2014): generator turns noise into fakes; discriminator classifies real vs fake; trained as a two-player minimax game. Problems: mode collapse (generator produces little variety), unstable training, vanishing gradients. Variants: DCGAN, conditional GAN, CycleGAN (unpaired image translation), StyleGAN.
  • KEYDiffusion models: a fixed forward process adds Gaussian noise over many steps; a network (usually a U-Net) learns to predict and remove the noise. Sharp, diverse images and stable training, but slow sampling (many steps). Latent diffusion (Stable Diffusion) works in a compressed latent space for speed.
  • KEYCLIP (OpenAI): trained contrastively on ~400M image–caption pairs to pull matching pairs together and push others apart; enables zero-shot image classification and guides text-to-image models.
  • Evaluating images: FID (lower is better) and Inception Score (higher is better).
05LLMs

Introduction to Large Language Models

  • KEYLLM = a transformer language model with billions of parameters, pre-trained with self-supervision on web-scale text. Self-supervised: labels come from the text itself (next word, masked word), no human labelling.
  • KEYObjectives: causal LM / autoregressive (GPT, predict next token, best for generation); masked LM (BERT, predict hidden tokens using both sides, best for understanding); span corruption / seq2seq (T5).
  • Scale: GPT-2 1.5B, GPT-3 175B. Scaling laws: loss falls predictably with more parameters, data and compute. Larger models show emergent abilities such as in-context learning.
  • KEYIn-context learning: zero-shot (instruction only), one-shot, few-shot (examples in the prompt). No weights change. Examples use up the context window.
  • KEYPrompt engineering: clear instructions, role/persona, delimiters, output format, examples, chain-of-thought ("think step by step") for reasoning, self-consistency (sample several reasoning paths, take the majority), ReAct (reason + act with tools).
  • KEYDecoding settings: greedy (deterministic, can repeat itself), random sampling, temperature (low = focused, high = creative), top-k, top-p, max new tokens, stop sequences.
  • Limits: hallucination (fluent but false), knowledge cutoff, fixed context window, bias from training data, cost and latency, weak arithmetic.
  • Model types: base/foundation model (raw pre-trained), instruction-tuned / chat model, open-weight (Llama, Mistral) vs closed API (GPT-4, Claude, Gemini). Multimodal models take images as well as text.
06Lifecycle

Generative AI project lifecycle

  • KEYScope narrowly: one task (summarise tickets) needs a smaller model than an open-ended assistant. Choose between an existing foundation model and pre-training your own (rarely worth it; only for very specialised domains like BloombergGPT for finance).
  • KEYInstruction fine-tuning: supervised training on prompt–completion pairs (e.g. "Summarise: … → summary"). Full fine-tuning updates every weight, needs memory like pre-training, and risks catastrophic forgetting of other tasks. Remedies: multi-task fine-tuning (FLAN), or PEFT.
  • KEYPEFT (parameter-efficient fine-tuning): freeze the base model, train a small number of parameters. Selective (some layers), reparameterisation = LoRA (low-rank matrices A, B beside frozen W; trainable r(d + k)), additive = adapters (small layers inserted) and soft prompts / prompt tuning (trainable virtual-token embeddings, the model unchanged). QLoRA = LoRA on a 4-bit quantised model. PEFT gives small checkpoints per task and less forgetting.
  • KEYRLHF: (1) supervised fine-tune; (2) humans rank model outputs → train a reward model; (3) optimise the LLM against the reward with PPO, with a KL-divergence penalty to a frozen reference model so it doesn't drift into reward hacking. Goals: helpful, honest, harmless (HHH). Alternatives: DPO (no separate reward model), RLAIF / Constitutional AI (AI feedback from written principles).
  • KEYEvaluation: ROUGE (summaries, recall), BLEU (translation, precision), perplexity; benchmarks GLUE/SuperGLUE (understanding), MMLU (knowledge across 57 subjects), BIG-bench, HELM (holistic: accuracy, fairness, toxicity …). Human evaluation and LLM-as-judge for open-ended output.
  • KEYRAG (retrieval-augmented generation): split documents into chunks → embed → store in a vector database → at query time retrieve the most similar chunks → put them in the prompt. Gives current, private, citable knowledge and fewer hallucinations, without retraining.
  • KEYLangChain: framework for LLM apps — model wrappers, prompt templates, chains (fixed sequence of calls), agents (the LLM decides which tools to call, e.g. ReAct), memory (conversation history), document loaders, text splitters, retrievers and vector stores.
  • KEYDeployment optimisation: quantisation (fp32 → int8/int4, smaller and faster), distillation (small student learns from a large teacher's outputs), pruning (remove near-zero weights). Also caching, batching, choosing hosted API vs self-hosted.
  • Compute: Chinchilla rule of thumb ~20 training tokens per parameter; many earlier models were under-trained for their size.
07Responsible

Responsible AI

  • KEYPrinciples: fairness, reliability & safety, privacy & security, inclusiveness, transparency, accountability (Microsoft's six); also explainability and human oversight.
  • KEYBias: comes from training data (historical, representation, measurement bias), labelling and deployment context. Models can amplify stereotypes (e.g. gendered job roles). Mitigate with representative data, bias audits, fairness metrics, debiasing and human review.
  • KEYHallucination: confident, plausible but wrong output (fake citations). Causes: the model predicts likely text, not verified facts. Mitigate: RAG with sources, lower temperature, ask for citations, verification steps, human-in-the-loop for high-stakes use.
  • Toxicity & safety: content filters / guardrails on input and output, RLHF, Constitutional AI, red-teaming (deliberately attacking the model to find failures). Prompt injection and jailbreaks try to override instructions.
  • Privacy: models can memorise and leak personal data; mask PII, minimise data, get consent, follow GDPR / India's DPDP Act 2023. Don't paste confidential data into public tools.
  • Intellectual property: training on copyrighted works and ownership of generated output are unsettled legal questions; prefer licensed data and track provenance.
  • Transparency: model cards and datasheets document data, intended use and limits; disclose AI-generated content; watermarking helps detect it.
  • Governance: risk-based regulation (EU AI Act tiers: unacceptable, high, limited, minimal risk), AI policies, human accountability, monitoring after deployment. Also environmental cost of training large models.

Last-minute traps

Each line is a statement a distractor is likely to flip. If you can say why each is right, you are ready.

  • Stemming chops suffixes (may not give a real word); lemmatization returns the dictionary form.
  • A word in every document has IDF = 0, so TF-IDF = 0.
  • One-hot vectors carry no similarity; all pairs are orthogonal.
  • CBOW: context → word. Skip-gram: word → context (better for rare words).
  • Word2Vec/GloVe are static; BERT embeddings are contextual.
  • Vanishing gradients → LSTM/GRU; exploding gradients → gradient clipping.
  • LSTM has 3 gates + a cell state; GRU has 2 gates and no separate cell.
  • Teacher forcing feeds the true previous token during training.
  • Beam width 1 = greedy.
  • Scale by √d_k, not d_k. Attention weights sum to 1.
  • Transformers need positional encoding; attention alone is order-blind.
  • Decoder self-attention is masked; cross-attention takes Q from the decoder, K/V from the encoder.
  • Self-attention is O(n²) in sequence length but runs in parallel.
  • BERT = encoder, masked LM, bidirectional. GPT = decoder, next token. T5 = encoder–decoder.
  • Discriminative learns P(y|x); generative learns P(x) / P(x,y).
  • VAE loss = reconstruction + KL; the reparameterisation trick makes sampling differentiable.
  • GAN failure with little variety = mode collapse.
  • Diffusion: forward adds noise (fixed), reverse removes it (learned).
  • CLIP is contrastive image–text training, enabling zero-shot classification.
  • Few-shot prompting changes no weights.
  • Temperature up = more random; T → 0 = greedy.
  • Top-p picks a variable number of tokens; top-k a fixed number.
  • Full fine-tuning risks catastrophic forgetting; PEFT reduces it.
  • LoRA trainable params = r(d + k); base weights are frozen; no added inference latency once merged.
  • Prompt tuning trains soft prompt embeddings, not the words you type.
  • RLHF order: SFT → reward model → PPO. The KL penalty prevents reward hacking.
  • DPO needs no separate reward model.
  • ROUGE → summarization (recall); BLEU → translation (precision).
  • Lower perplexity is better.
  • RAG adds knowledge without retraining; fine-tuning changes behaviour/style.
  • LangChain chain = fixed steps; agent = LLM chooses tools.
  • Quantisation = lower precision; distillation = student learns from teacher; pruning = remove weights.
  • Chinchilla: about 20 tokens per parameter.
  • Hallucination is reduced, never eliminated, by RAG and low temperature.
  • Red-teaming = deliberately attacking the model to find failures.
  • EU AI Act is risk-based: unacceptable, high, limited, minimal.
